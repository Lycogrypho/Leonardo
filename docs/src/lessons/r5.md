# R5 — Equations

**Goal:** solve equations, inequalities and systems — and understand the one thing `solve` does
that will surprise you.

## One equation, one unknown

```scala mdoc:passthrough
lesson.show("solve(2x + 6 = 0, x)")
```

## Why does that look like an assignment?

Because it is one. Read the echo again — `x := -3.0`, the exact shape [R3](r3.md) taught. **`solve`
does not merely report the root, it stores it**, so the next line that mentions `x` uses it:

```scala mdoc:passthrough
lesson.show("x + 1")
```

That is convenient when you want to carry a result forward into further work, and a trap when you
do not: a second `solve` would substitute the first answer before doing anything at all. This is
the stale-binding problem R3 warned about, arriving from a command you did not think of as an
assignment.

**Clear it between problems:**

```scala mdoc:passthrough
lesson.show("unset x", "solve(x^2 - 4 = 0, x)")
```

Two roots, and notice they bound as `x_1` and `x_2` rather than `x` — so `x` itself is untouched.
Proof, rather than assertion:

```scala mdoc:passthrough
lesson.show("unset x")
```

Nothing to clear. The habit to build is simple: **when a `solve` answer looks wrong, check `env`
first.**

## Symbolic coefficients

```scala mdoc:passthrough
lesson.show("solve(a*x + b = 0, x)", "unset x")
```

That is what makes this a computer algebra system rather than a numerical solver: it rearranged
the equation without ever knowing what `a` and `b` are.

## When there is no closed form

```scala mdoc:passthrough
lesson.show("solve(cos(z) = z, z)", "unset z")
```

No formula exists for that root, so the answer is numeric — and which kind you got is visible in
the answer itself rather than hidden behind a flag.

## Naming an equation

An equation is an ordinary value, so you can store one and solve it later:

```scala mdoc:passthrough
lesson.show("eq := x^2 - 5x + 6 = 0", "solve(eq, x)", "unset x_1", "unset x_2")
```

## Inequalities

The answer to an inequality is a **region**, and the language can say so:

```scala mdoc:passthrough
lesson.show("solve(2x + 6 > 0, x)", "solve(x^2 - 4 > 0, x)")
```

The second is a union, written with `or` — an ordinary connective here, not a special kind of
object. A bounded region comes back as an `and`, and you can pose a combination directly:

```scala mdoc:passthrough
lesson.show("solve(x^2 - 4 < 0, x)", "solve(2x > 2 and x < 5, x)")
```

Note there is no `:=` in any of those: a region is not a value to assign, so nothing was stored.
Only a definite answer binds.

## Systems

`solveSystem` takes a row of equations, then the unknowns in order:

```scala mdoc:passthrough
lesson.show("solveSystem([[x + y = 3, x - y = 1]], x, y)")
```

The `[[...]]` brackets are the matrix literal — one row — which is also the shape the answer comes
back in. [R6](r6.md) is about those.

## Equations are values too

An equation evaluates as soon as everything in it is known:

```scala mdoc:passthrough
lesson.show("2 + 2 = 4", "sin(pi) = 0")
```

The second is `true` because equality here is **tolerance-based** at the display precision.
`sin(pi)` is not exactly zero in floating point — π is not exactly π — and answering `false`
would be technically correct and practically useless. [R8](r8.md) is about getting the exact
answer when you want it.

## Try it yourself

A rectangle has perimeter 20 and area 24. Find its sides.

<details>
<summary>Answers</summary>

The obvious attempt is a system:

```scala mdoc:passthrough
lesson.show("solveSystem([[2w + 2h = 20, w * h = 24]], w, h)")
```

Declined — the unchanged-answer shape from [R4](r4.md). **`solveSystem` is linear only**, and
`w * h` is not, so it did not guess. Substitute by hand (`h = 10 - w`) and solve the quadratic
that remains:

```scala mdoc:passthrough
lesson.show("solve(w * (10 - w) = 24, w)")
```

Sides 4 and 6 — the two roots are the same rectangle, seen twice.
</details>

## What you learned

- **`solve` binds its answer** — one root as the variable, several as `x_1`, `x_2`, … Use `unset`
  between problems, or the next solve starts from the last one.
- It handles linear and quadratic exactly, symbolic coefficients included, and falls back to
  numeric roots when no formula exists.
- **An inequality's answer is a region**, written with `and` / `or` in the same language you
  asked in — and regions do not bind.
- `solveSystem([[...]], x, y)` is **linear only**, and declines rather than guessing.
- Equality between numbers is **tolerant**, so `sin(pi) = 0` is `true`.
