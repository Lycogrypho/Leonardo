## Why there is no picture on this page

`plot` is the one command these lessons cannot run for you. Every other transcript here is
produced by executing a real session when the site is built — but drawing needs a page to draw
on, so `plot` lives in the browser front end rather than in the shared command set.

That is a deliberate choice rather than an omission: **a terminal cannot draw, and a command
that cannot do anything is worse than an absent one.** The same reasoning shapes [R10](r10.md).

So the plotting lines below are the one thing on this page you type rather than read — and you do

## Plotting

```text
> plot sin(x) x 0 6.28
(plotted 200 points)
```

The arguments are the shape you already know from [R4](r4.md) — *what*, *which variable*,
*from*, *to* — with an optional count on the end, defaulting to 200. Three siblings share it
exactly:

- **`points`** draws markers instead of a joined line;
- **`bode`** and **`nyquist`** draw the two standard frequency-response diagrams.

Sharing one argument syntax means there is nothing new to learn for any of them.

## The same grid, as numbers

`samples` takes those same arguments and prints the table the plotter would have drawn — and it
works everywhere, including here:

```scala mdoc:passthrough
lesson.show("samples sin(x) x 0 3.14159 5")
```

Five points from 0 to π, as *x* and *y* in two columns. **This is the command to reach for when
a figure looks wrong**: the numbers are the same ones the picture was built from, and numbers
are easier to argue with than pixels.

## When points go missing, you are told

A sweep drops any point where the expression has no finite value — a pole, or an argument
outside the function's domain. It counts what it dropped:

```scala mdoc:passthrough
lesson.show("samples 1/x x -1 1 11")
```

Ten rows, not eleven: the grid landed on `x = 0`, where `1/x` has no value.

That closing note is the whole point of this section. **A plot of ten points where you asked for
eleven looks exactly like a plot of eleven** — the curve simply passes through — so without the
count the pole would be invisible. Reporting `N of M` costs a line and turns a silent gap into a
fact you can act on.

## When a grid is wrong in principle, it is refused

Some expressions have values *only at whole numbers*. Anything built with `sum`, `product` or
`tabulate` over a range that depends on the variable you are sweeping is one:

```scala mdoc:passthrough
lesson.show("samples sum(k, k, 1, n) n 0 100")
```

Leonardo refused, **and named the grid that works**.

It could have drawn instead. Over `0 … 100` with the default 200 points the step is `100/199`,
so exactly one sample lands on a whole number — and a chart of that one point would be a true
picture of nothing anyone asked for, its spacing an artefact of where the step happened to fall
rather than anything about the function. Following the advice:

```scala mdoc:passthrough
lesson.show("samples sum(k, k, 1, n) n 0 10 11")
```

One point per integer — the triangular numbers, which is what the function actually has. Swap
`samples` for `plot` and the same line draws it.

Note the two conditions: the expression must be whole-numbered **and** the grid must actually be
missing points. A grid already landing on the integers is never refused, so the advice above
works rather than being an obstacle.

## Try it yourself

`x^3 - 2x` crosses zero somewhere between 1 and 2. Find roughly where, then get it exactly.

<details>
<summary>Answers</summary>

```scala mdoc:passthrough
lesson.show("samples x^3 - 2x x 1 2 6")
```

The sign changes between 1.4 and 1.6. Exactly:

```scala mdoc:passthrough
lesson.show("solve(x^3 - 2x = 0, x)", "unset x_1", "unset x_2", "unset x_3")
```

Three roots — `0` and `±√2` — of which `1.41421` is the one bracketed above.
</details>

## What you learned

- `plot`, `points`, `bode` and `nyquist` are **browser-only**, and share one argument syntax with
  `samples`, which works everywhere.
- **A sweep reports what it dropped** (`N of M`), so a pole cannot hide inside a smooth-looking
  curve.
- A whole-numbered expression is **refused with a working recipe** rather than drawn on a grid
  that misses it — and only when points are genuinely being lost.
- When a figure looks wrong, print the numbers.
