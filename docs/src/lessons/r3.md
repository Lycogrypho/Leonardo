# R3 — Naming things

**Goal:** give names to values and to formulas, understand why the two behave differently, and
learn the command that gets you out of trouble.

## Assignment is `:=`

```scala mdoc:passthrough
lesson.show("a := 3", "a + 1")
```

The echo repeats what was stored, which is worth reading rather than skipping — later in this
lesson it is how you tell a value from a formula.

## Why not `=`?

Because `=` already means something, and it is not assignment:

```scala mdoc:passthrough
lesson.show("a = 4")
```

That is an **equation**, and Leonardo answered it: `a` is 3, so `a = 4` is false. An equation is
a thing you can state, test and solve, which is what makes `solve(x^2 = 4, x)` meaningful in
[R5](r5.md). Had `=` been assignment, none of that would be sayable.

Two symbols, two jobs: **`:=` stores, `=` relates.**

## A formula keeps its variables

Assign something containing a free variable and you get a **definition** rather than a value:

```scala mdoc:passthrough
lesson.show("g := sin(t) + t", "g")
```

Look at the echo: it repeated the *formula*, where `a := 3` repeated a number. Nothing was
computed, because `t` has no value and there was nothing to compute. Give `t` one and `g`
follows:

```scala mdoc:passthrough
lesson.show("t := 0", "g")
```

## Definitions are late-bound, and that is the point

A definition is re-read every time you use it, so redefining what it depends on updates it —
without touching the definition:

```scala mdoc:passthrough
lesson.show("h := 2 * g", "h", "t := 1", "h")
```

`h` means *"twice whatever `g` is"*, and `g` means *"`sin(t) + t` for whatever `t` is"*. Change
`t`, and both move. That is how you build a model up in layers and then explore it by changing
one number at the bottom.

## When you want the opposite, freeze it

Sometimes a name should record a result rather than a relationship. `consolidate` evaluates
**now** and stores the answer, so later changes cannot reach it:

```scala mdoc:passthrough
lesson.show("frozen := consolidate(2 * g)", "t := 2", "frozen", "h")
```

`h` moved with `t`; `frozen` did not. Use `consolidate` for a measurement you have already
taken, and plain `:=` for a relationship you want kept live.

## Seeing what you have

```scala mdoc:passthrough
lesson.show("env")
```

`env` lists the settings as well as the names — values first, then definitions — so it answers
both "what did I call that?" and "what state am I in?".

## `unset` — the command that gets you unstuck

```scala mdoc:passthrough
lesson.show("unset t", "g")
```

With `t` gone, `g` is a formula again.

**This is the most useful command in the lesson**, because the commonest confusion at this
prompt is an answer that comes back as a number when you expected algebra. The cause is almost
always a name still bound from earlier. Two things bind without your typing `:=`:

- a `:=` you have forgotten about, which `env` will show you;
- **`solve`, which stores its own answer** — see [R5](r5.md), where it earns its own section.

When something reads oddly, `env` then `unset` is the fix.

## Names the language has taken

```scala mdoc:passthrough
lesson.show("e := 3", "simplify := 1")
```

Constants and command words are refused rather than silently shadowed — otherwise the binding
would be unreachable, since `e` always parses as the constant and `simplify` always starts a
command.

## Try it yourself

Define `area` as the area of a circle of radius `r`, evaluate it at `r = 2`, then make `area`
symbolic again.

<details>
<summary>Answers</summary>

```scala mdoc:passthrough
lesson.show("area := pi * r^2", "r := 2", "area", "unset r", "area")
```

Note the first echo: `area` stored the *formula*, with `pi` already folded to a number because
that much was computable.
</details>

## What you learned

- **`:=` stores, `=` relates.** An equation is a value you can test and solve.
- A right-hand side with free variables becomes a **late-bound definition** that tracks its
  dependencies; `consolidate` freezes the current answer instead.
- The echo tells you which you got: a number or a formula.
- `env` shows bindings and settings; **`unset` is what you reach for when an answer is
  unexpectedly numeric.**
