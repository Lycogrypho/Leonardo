# R6 — Matrices

**Goal:** build matrices, do algebra with them, pull a decomposition apart, and read the display
when it gets wide.

## A matrix is rows of rows

```scala mdoc:passthrough
lesson.show("A := [[1, 2], [3, 4]]", "B := [[0, 1], [1, 0]]")
```

## Why the double brackets?

Because the outer pair is the **matrix** and each inner pair is a **row**. One pair alone is not
a matrix at all:

```scala mdoc:passthrough
lesson.show("[1, 2]")
```

It is the same `[[...]]` you met in [R5](r5.md)'s `solveSystem`, and it is what makes a vector
need no separate type:

```scala mdoc:passthrough
lesson.show("[[1, 2, 3]]", "[[1], [2], [3]]")
```

A row vector is a one-row matrix; a column vector is a one-column matrix. There is no third
thing to learn, and every matrix operation applies to both.

## Arithmetic uses the ordinary operators

```scala mdoc:passthrough
lesson.show("A + B", "A * B", "2 * A")
```

`A * B` is the matrix product, so **order matters** — worth seeing once rather than taking on
trust:

```scala mdoc:passthrough
lesson.show("B * A")
```

## Determinant, inverse, transpose

```scala mdoc:passthrough
lesson.show("det(A)", "inv(A)", "transpose(A)")
```

Division by a matrix is multiplication by its inverse, so `1/A` means what you would hope:

```scala mdoc:passthrough
lesson.show("1/A")
```

A singular matrix has no inverse, and you already know what that answer looks like:

```scala mdoc:passthrough
lesson.show("inv([[1, 2], [2, 4]])")
```

Unchanged — declined, exactly as in [R4](r4.md). That matrix's rows are proportional, so there
is no inverse to give, and nothing was invented.

## Reading a wide result

One line per row is easier once a matrix is more than a line wide:

```scala mdoc:passthrough
lesson.show("pretty on", "inv(A)", "pretty off")
```

`pretty` is a display setting like `precision`, saved with your session ([R9](r9.md)).

## Decompositions

Each returns a **row of matrices**, which is where [R3](r3.md)'s naming and this lesson's
literal meet:

```scala mdoc:passthrough
lesson.show("eigen(A)")
```

```scala mdoc:passthrough
lesson.show("L, U, P := lu(A)", "L", "U")
```

**Tuple assignment is what makes a multi-part result usable** — one name per part, and the count
must match exactly. `qr(A)` and `eig(A)` have the same shape; `eig` gives eigenvectors beside
eigenvalues.

Eigenvalues may be complex, and those come back as complex numbers rather than being dropped:

```scala mdoc:passthrough
lesson.show("eigen([[0, -1], [1, 0]])")
```

That is a rotation by a quarter turn, which has no real eigenvalue at all.

## Symbolic entries

Nothing above required numbers:

```scala mdoc:passthrough
lesson.show("det([[a, b], [c, d]])")
```

## Try it yourself

`A` has trace 5 and determinant −2, so the Cayley–Hamilton theorem says `A² − 5A − 2I` should be
the zero matrix. Check it.

<details>
<summary>Answers</summary>

```scala mdoc:passthrough
lesson.show("A^2 - 5*A - 2*eye(2)")
```

`eye(n)` is the identity matrix and `zeros(r, c)` its counterpart — both constructors rather
than literals you have to type out.
</details>

## What you learned

- `[[...], [...]]` is a matrix: **outer brackets the matrix, inner brackets each row**. A vector
  is just a one-row or one-column one.
- `+`, `*`, `det`, `inv`, `transpose` work as written, `1/A` is the inverse, and **order matters**
  in a product.
- **A singular or non-conforming operation declines** rather than erroring — R4's convention
  again.
- `pretty on` stacks rows; tuple assignment unpacks `lu`/`qr`/`eig`; complex eigenvalues survive.
