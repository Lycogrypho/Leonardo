# R4 — Calculus

**Goal:** differentiate, integrate, take limits and expand series — and learn to read the answer
Leonardo gives when it cannot do one of them.

## Why every command names the variable

`derive(f, x)`, `integral(f, x)`, `limit(f, x, a)` — the variable is always an argument, never
inferred. That is not ceremony:

```scala mdoc:passthrough
lesson.show("derive(x * y, x)", "derive(x * y, y)")
```

Same expression, two different questions, two different answers. Guessing which you meant would
be guessing at mathematics, so Leonardo asks. In exchange, **every command here has the same
shape** — what, then with respect to what — and one you have read is one you can read.

## Derivatives

```scala mdoc:passthrough
lesson.show("derive(x^3, x)", "derive(sin(x) * x, x)", "derive(exp(2x), x)")
```

Product rule and chain rule, applied without being named.

A **second derivative** is `derive` twice. The prompt's `derive` takes exactly one variable, so
you nest it:

```scala mdoc:passthrough
lesson.show("derive(derive(x^4, x), x)")
```

And a **partial derivative** needs no special syntax at all — naming the variable *is* what
makes it partial, as the first section showed.

## Integrals

Three arguments is the antiderivative; five is a definite integral:

```scala mdoc:passthrough
lesson.show("integral(x^2, x)", "integral(x^2, x, 0, 3)")
```

The interesting ones are where technique matters, and you are not asked to choose it:

```scala mdoc:passthrough
lesson.show("integral(x * exp(x), x)", "integral(1/(x^2 - 1), x)")
```

The first is integration by parts; the second a partial-fraction decomposition.

## When it cannot, it says so by doing nothing

```scala mdoc:passthrough
lesson.show("integral(exp(x^2), x)")
```

The answer is **the integral itself, unchanged**.

That is not an error message and not a failure to try. `exp(x^2)` has no elementary
antiderivative — no combination of the usual functions differentiates to it — so there is
nothing to return, and returning something plausible would be far worse than returning nothing.

> **An answer identical to your question means "declined".** You will meet that shape all over
> Leonardo: `limit`, `solve` and the transforms all do it.

It is worth trusting, because the alternative is a confident wrong answer you have no way to
spot.

Some non-elementary integrals are important enough to have names, and those it knows:

```scala mdoc:passthrough
lesson.show("integral(sin(x)/x, x)", "integral(exp(-x^2), x)")
```

`Si` is the sine integral; `erf` the error function. Both are real answers — just not answers
writable with `sin`, `exp` and friends.

## Limits

```scala mdoc:passthrough
lesson.show("limit(sin(x)/x, x, 0)", "limit((x^2 + 1)/(2x^2 - x), x, inf)")
```

`inf` is a literal you can use anywhere a limit point is wanted.

A one-sided limit takes a trailing `+` or `-`, which is how you ask about a pole from one side:

```scala mdoc:passthrough
lesson.show("limit(1/x, x, 0, +)", "limit(1/x, x, 0, -)")
```

Two different answers, which is exactly why the two-sided limit there does not exist.

## Series

```scala mdoc:passthrough
lesson.show("taylor(exp(x), x, 0, 4)")
```

The arguments are *what*, *in which variable*, *about which point*, *to what order*.
`maclaurin(exp(x), x, 4)` is the same thing, since a Maclaurin series is a Taylor series about
zero.

The centre need not be a number:

```scala mdoc:passthrough
lesson.show("taylor(x^2, x, a, 2)")
```

## Try it yourself

Find where `x^3 - 3x` has a horizontal tangent: differentiate it, then solve the result for zero.

<details>
<summary>Answers</summary>

```scala mdoc:passthrough
lesson.show("derive(x^3 - 3x, x)", "solve(3x^2 - 3 = 0, x)")
```

Horizontal tangents at `x = ±1`.

Note that the derivative had to be **copied into** the second line rather than nested:

```scala mdoc:passthrough
lesson.show("unset x_1", "unset x_2", "solve(derive(x^3 - 3x, x) = 0, x)")
```

That declined — the unchanged-answer shape again. `solve` was handed an equation whose left side
is still a `derive(...)` node, and its solver works on polynomial structure it can read, so it
did not pretend. Compute first, then solve.
</details>

## What you learned

- **The variable is always an argument, and exactly one.** Nest `derive` for a second
  derivative; naming the variable is what makes a derivative partial.
- `integral(f, x)` is the antiderivative; `integral(f, x, a, b)` is a number.
- **An unchanged answer means "declined"** — the single most useful convention in the library,
  and the reason you can trust the answers that do come back.
- `limit` takes an optional `+`/`-` and understands `inf`; `taylor` takes a centre, which may be
  symbolic.
