# R10 — The terminal REPL

**Goal:** run the same REPL outside the browser, and know the three ways it differs.

## Getting it

From a checkout of the project:

```bash
sbt repl
```

Or as a dependency in your own build:

```scala
libraryDependencies += "it.grypho" %% "leonardo-repl" % "@VERSION@"
```

## Why `leonardo-repl` and not `leonardo`?

Because they are two artifacts, and the REPL is the larger one. It needs a terminal library — for
line editing, history and colour — which a program that merely wants to differentiate an
expression has no business downloading.

So the split runs the other way from what you might expect: **`leonardo` is the library, and
`leonardo-repl` adds the prompt on top of it.** Depend on the first unless you specifically want
to embed or extend the REPL itself. [Getting Started](../getting-started.md) has both
coordinates, and [Lessons: in your program](library.md) is the branch for using the library
directly.

## It is the same command language

Everything from R1 to R9 works unchanged, because both REPLs run the same session underneath:

```scala mdoc:passthrough
lesson.show("f := x^2 + 1", "derive(f, x)", "integral(f, x, 0, 1)")
```

There is no terminal dialect to learn. What follows is the complete list of differences.

## Difference 1 — it cannot draw

`plot`, `points`, `bode` and `nyquist` exist only in the browser.

They are not missing by oversight. As [R7](r7.md) put it, **a command that cannot do anything is
worse than an absent one** — so rather than accepting `plot` and printing an apology, the
terminal REPL does not claim the word at all. `samples` is what it has instead, and it is the
same computation without the picture.

## Difference 2 — real files

`:save` and `:load` take a **path**, and what you get is a text file you can keep, edit, diff and
email:

```text
> :save ~/work/session.leo
saved to ~/work/session.leo
```

In the browser those same commands write to the browser's own storage ([R9](r9.md)). Identical
spelling, different backing store — which is the point.

This is where a session being a *script* rather than a snapshot pays off: the file is readable,
and you can edit it before replaying it.

## Difference 3 — a terminal's comforts

Line editing, history that survives between runs, and **syntax colouring** as you type:

```scala mdoc:passthrough
lesson.show("colors", "colors light", "colors dark")
```

`dark`, `light` and `none` are the schemes. The browser has no highlighting, so — consistently
with Difference 1 — the setting is simply not offered there rather than offered and inert.

There are also **Greek chords**: `ALT-g` followed by a letter inserts the matching Greek letter,
so `theta` can be entered as a single character where that reads better. Ordinary editing keys
are untouched; `ALT-b` still means *backward-word*.

## Help without leaving the prompt

`help` prints the whole command summary. `help <topic>` goes deeper on one of them:

```scala mdoc:passthrough
lesson.show("help exact")
```

It works in both REPLs, and it is faster than coming back here to check a spelling.

## What you learned

- `sbt repl`, or the `leonardo-repl` artifact, gives the same command language offline —
  **`leonardo` is the library, `leonardo-repl` adds the prompt.**
- **No plotting** in the terminal; use `samples`.
- `:save` / `:load` use real paths there and browser storage in the page.
- Line editing, history, `colors` and Greek chords are the terminal's own.
- `help` and `help <topic>` answer most questions without leaving the session.
